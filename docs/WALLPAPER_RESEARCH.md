# Synchronized wallpaper on macOS 26

## What macOS exposes

Apple documents a **Show on all Spaces** switch in Wallpaper settings that shares a wallpaper across desktops and displays. The public AppKit setter takes an `NSScreen` and has options for image placement. An Apple Frameworks Engineer confirmed in June 2026 that no API sets desktop images for all Spaces on a screen. A developer report on Tahoe describes the switch turning off after an AppleScript wallpaper update. [Wallpaper settings](https://support.apple.com/en-us/guide/mac-help/-mchlp1103/mac), [AppKit setter](https://developer.apple.com/documentation/appkit/nsworkspace/setdesktopimageurl(_:for:options:)), [Apple Frameworks Engineer](https://developer.apple.com/forums/thread/834630), [Tahoe report](https://developer.apple.com/forums/thread/814926)

A long-running app can use `NSWorkspace.activeSpaceDidChangeNotification` and reapply the last selected image on the visible desktops. Inactive Spaces retain their previous wallpaper until visited. This also leaves a chance of showing the previous image during a transition. [AppKit notification](https://developer.apple.com/documentation/appkit/nsworkspace/activespacedidchangenotification), [example implementation](https://github.com/tom-james-watson/wallpaper-macos)

## Recommended prototype for all Spaces

Use the per-user wallpaper store at `~/Library/Application Support/com.apple.wallpaper/Store/Index.plist`. The `wallall` implementation writes one static-image choice to `AllSpacesAndDisplays.Desktop`, sets its parent `Type` to `desktop`, and restarts the user's `WallpaperAgent` so macOS loads the new choice. It preserves per-Space and per-display entries. The nested binary `Configuration` describes an image-file URL. The global entry's precedence comes from observed behavior in that implementation. Apple does not document this storage format or reload behavior as an API. [wallall implementation](https://github.com/TresChar/wallall/blob/main/wallall#L59-L123)

On macOS 26.6.2, the initial `AllSpacesAndDisplays` and `SystemDefault` entries both had `Type = linked`. A live test converted the global entry to `individual` and moved the old linked choice to `Idle`. After reloading the agent, AppKit reported the new image on the active internal display, and the stored screen saver choice still matched the original. The original store was restored after the probe. Screen saver playback, inactive Spaces, and multiple displays still require direct verification.

In OmaQuote, isolate this operation in a Swift component. Read the current plist on each change, validate its shape, and test the transformation on copies. Back up the original and replace the on-disk plist atomically. Reload the agent in the active user's GUI session and confirm that the new image is applied before reporting success. Verify on Tahoe with distinct wallpapers on multiple displays and inactive Spaces, then create a Space, reconnect a display and wake the Mac. Check presets with a linked wallpaper and screen saver because changing `Type` to `desktop` may affect how the system selects the screen saver even if `Idle` is preserved. Compare that behavior with updating the active `Linked` image in place, which may also change the paired screen saver. Test whether reloading the agent causes a visible flash.

## OmaQuote integration

The app picks one readable image from the chosen folder on startup, at each rotation interval, or when the user clicks **Next Wallpaper**. Defaults are `~/wallpapers` and 10 minutes. The wallpaper interval is separate from the quote interval, and the wallpaper preferences are stored outside the shared Linux `config.json` schema. After a confirmed change, the existing `advanceOnWallpaperChange` flow runs once. The five-second observer is suspended during the change and resumes with the new baseline.
